# CRUX Experimental Evaluation Artifacts

This directory contains experimental artifacts, raw CRUX static analysis reports, per-site lock validation tables, benchmark harnesses, and end-to-end performance measurements evaluated on a dedicated **CloudLab** bare-metal server.

---

## 1. Hardware & Testbed Environment
* **Server:** CloudLab Utah (`amd008` / `c6520`)
* **CPU:** Intel Xeon Gold 6338 (20 cores, 40 threads @ 2.00 GHz)
* **RAM:** 192 GB DDR4 ECC
* **OS:** Ubuntu 22.04 LTS (Kernel 5.15.0-x86_64)
* **Compiler & LLVM:** Clang/LLVM 14.0.0, WLLVM 1.3.0
* **Static Analyzer:** CRUX 3.0

---

## 2. Directory Structure

Each evaluated software project contains 4 standard artifacts:

```text
experiments/cloudlab_results/
├── README.md                  # Evaluation guide (this file)
├── machine_specs2.txt         # Server hardware & environment dump
└── <project>/                 # memcached, librdkafka, h2o, xen, postgres...
    ├── <project>_report.json  # [1] Raw CRUX analysis report
    ├── results_<project>.csv  # [2] Per-site lock validation table
    ├── global_performance.txt # [3] End-to-end multi-trial performance report
    └── bench_<name>.c         # [4] Standalone C benchmark reproduction harness
```

---

## 3. Artifact Description

### A. Raw CRUX JSON Report (`*_report.json`)
Machine-readable output generated by CRUX when analyzing LLVM IR bitcode (`.ll`), including discovered lock sites, graph edge counts, analysis runtime, and classified useless locks.

### B. Per-Site CSV Table (`results_*.csv`)
Tabular breakdown containing strictly 1 row per lock site:
* `Lock_ID`, `File`, `Function`, `Line`: Source location.
* `Pattern`: Formal uselessness reason (`LOCAL_VARS`, `READ_ONLY`, `REDUNDANT`, `EMPTY_CS`).
* `True_Positive`: Manual validation by source code audit (`Yes`).
* `Base_Throughput` / `Patched_Throughput`: Throughput before and after patch.
* `Throughput_Gain`: Percentage increase (`+%`).
* `Base_Latency` / `Patched_Latency`: Latency / execution time before and after patch.
* `Latency_Gain`: Positive percentage latency improvement (`+%`).

### C. Global Performance Report (`global_performance.txt`)
Detailed summary of macro-benchmarks and full-system performance across **10 consecutive trials** ($\mu \pm \sigma$) with 0 crashes, reporting throughput, average latency, and tail latency (P99).

### D. Benchmark Reproduction Code (`bench_*.c`)
Standalone, self-contained C programs to reproduce multi-threaded contention and benchmark performance improvements with `gcc -O3 -pthread`.
